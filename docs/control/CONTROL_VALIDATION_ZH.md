## 1. 实现内容

| 文件 | 已实现能力 | 限制 |
|---|---|---|
| `command_bridge.py` | 显式会话状态机、有限动作段、等待期保持、原始观察年龄、工作空间/速度/加速度/单步变化检查、反馈跟踪与故障停机 | 调用方必须串行调用状态机并提供单调时钟；没有硬实时保证 |
| `hardware_backend.py` | 控制器契约、纯ROS目标消息转换、理想化控制器模拟、HTTP/ROS图只读审计 | `HardwareBackend`真实写入未实现；`acquire/write`始终拒绝，无配置开关可解锁 |
| `run_control.py` | 模拟场景、故障注入、当前硬件就绪检查、输出完整报告 | `--mode hardware`当前只检查并阻断，不执行动作 |
| `config/control_simulation.json` | 可重复的软件测试频率、范围与约束 | 仅模拟参数，不是现场批准的限值 |

状态流程：

```text
DISCONNECTED → HOLDING → WAITING → EXECUTING → HOLDING
任一活动阶段异常 → STOPPING → STOPPED 或 FAULT_UNCONFIRMED
```

- 先获得双臂与夹爪的会话令牌，逐tick核对所有权和反馈新鲜度；取得控制权失败时不向其他控制者的设备发停止命令。
- 接收预测时核对请求ID、原观察时间、RPC预算、诊断通过标记；检查全部50步再截取前K步，不隐藏非法尾段，不裁剪越界夹爪。
- 按训练的1/30秒动作步长消费有限段，模拟控制循环为200 Hz；等待推理时持续发送保持目标，不重写观察时间。
- 每个tick检查截止期、跟踪误差、IK状态和控制器健康；超时不补发积压命令。
- 部分下发失败时分别请求左臂、右臂、夹爪停止；三方确认都成功才记录STOPPED并释放会话。确认失败或释放失败为FAULT_UNCONFIRMED，不伪称已停止。
- 停止清空待执行段和请求，不恢复旧预测。新会话需新的控制桥实例与观察。

这里的stop确认是**需要硬件适配器实现的契约**。模拟器中的确认不证明现有机器人支持这套协议，也不证明软件停止等价于物理急停。

## 4. 如何运行

```bash
cd /home/user/forcevla-web/robot_control

# 合成数据、虚拟时间、零硬件输出
./run.sh control --mode simulate --output runs/my-control-simulation
./run.sh control --mode simulate --fault right_write_failure \
  --output runs/my-partial-failure

# 实时只读硬件状态与ROS图检查；预期退出码2表示尚不可执行
./run.sh control --mode audit \
  --prediction-dir runs/20261014-shadow-final/prediction_0000 \
  --output runs/my-control-readiness
```

`simulate`退出码0表示模拟场景已记录，需查看state和故障字段；不是任务成功声明。`audit/hardware`当前退出码2表示真实动作被阻断；输入或程序错误退出码1。`--mode hardware`不是可以绕过门槛的执行开关。

纯消息转换函数 `encode_targets()` 将米/xyz欧拉角转换为base_link下的ROS Pose和xyzw四元数，设置双臂可用位及14维关节种子，另返回两个归一化夹爪消息。它不建立ROS节点、不发布消息；不能把这部分实现误认为完整硬件后端。
