## 执行方式

复用已实际运行的MoveJ通路：完整m6_696模型/已安装QP核心离线求解 → 既有MoveJ规划器 → mux → ROS驱动 → 本机MarvinSDK → 双臂。运行时读取并核对规划器配置，每关节速度0.2rad/s、加速度0.5rad/s²；没有修改这些参数，不把它们当作硬件额定值。

实际动作按规划器重新定时，每个手臂目标通过实际关节和TCP反馈确认后继续。夹爪目标由驱动确认接收，实际位置持续记录，不作为每步到位等待条件。模型的1/30秒标签保留，但不表示本模式以30Hz执行；每轮完成后才重新观察，执行期间不做异步动作拼接。

夹爪目标显式限制到[0,1]，记录原始值和修正量，复用驱动fine速率与接管规则。实测两轮夹爪目标均为0；变化夹爪目标有软件测试和驱动回执处理，本次40步没有验证变化夹爪的物理效果。

原始力/力矩仅记录；用户要求删除的10N/1N·m停止条件没有恢复。保留关节边界、已有配置碰撞对、反馈时效、控制权和实际轨迹核对。碰撞模型仅覆盖现有机器人配置几何，不是完整桌面/工装环境验证；完成轮数不表示插接任务成功。

## 新观察、停止和记录

每轮使用该轮采集的观察ID、源时间和请求ID，全部图像/状态来源须晚于前一轮保持确认。不会从保存的历史预测启动，不刷新旧观察时间，也不在异常后自动重放剩余队列。推理或离线准备期间持续检查机器人状态并维持夹爪会话心跳。

网页停止、浏览器断开超过5秒、父进程断开、反馈异常或到位失败会终止后续目标，切断当前Planner输入并请求夹爪保持，通过反馈确认后释放。确认失败保留“停止未确认”状态。进程被强制杀死后的独立制动没有在本次实测中验收；原生MoveJ已下发的单点轨迹可能继续到该点，网页不把工作进程消失标记成停止成功。

原有native引擎的1～3步验证入口和资格条件保持独立，新模式明确标识为 `engine=movej`。本次没有伪造原生500Hz运动资格文件。
