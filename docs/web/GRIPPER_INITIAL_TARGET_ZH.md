# 夹爪回初始位（2026-10-15）

推理页面原“Restart Gripper”已改为“夹爪回初始位”。点击后明确发送左右归一化位置目标 `[0,0]`；按当前 `[0,1.6]rad` 标定对应两侧电机目标0rad。这个新操作替代推理页先前的失能/使能调用。原8081控制台自身的Restart Gripper没有修改。

## 实现与结果含义

使用夹爪驱动已有外部目标话题 `/control/gripperValueL`、`/control/gripperValueR`，各发送一条 `Float32(0.0)`。不调用 `/control/reset_grippers`，不修改零位、标定、增益或机械臂模式。

仅在Input=None、没有其他夹爪占用、双臂静止且本页闭环/HOME/其他控制任务结束后启动。已有驱动也会在夹爪被占用时拒绝外部目标。这条明确的初始目标操作不申请旧目标的claim，因此不要求先到达此前不可达的1.6rad目标。

目标发布后检查原始时间戳更新、驱动身份未变，以及两侧 `applied_target` 均读回0。界面显示目标已确认及确认时的实际反馈。**目标被接收不等于物理位置已经到位**；没有新增夹爪位置误差停止阈值，没有恢复已删除的执行阶段到位等待。部分发布失败或读回未确认不会自动重复发送。

网页沿用 `/api/v1/gripper-restart/*` 路由以保留兼容性，新记录标识 `operation=initial_target_v1`。旧重启历史保留，页面不把旧的重新使能结果当成新目标已发送。

## 验证

70项测试通过，覆盖两侧显式零目标、默认只读、被占用拒绝、部分发送失败、驱动身份变化、目标读回、不因实际位置偏差阻塞、重复请求、HOME/闭环互斥等。

真实ROS通道只读检查通过，发送命令数0。浏览器使用模拟后端验证目标读回为[0,0]、实际位置仍偏离时不虚报物理到位，以及390/320像素页面布局。正式8096页面已更新并做只读检查。本次开发没有实际向真机发送初始目标；由用户点击按钮触发。

主要代码：`forcevla_web/gripper_initial.py`、`scripts/run_gripper_initial.sh`、`forcevla_web/gripper_restart.py`。证据：`artifacts/gripper-initial-target-20261015/`。
