# 观察输入持续等待/异常的修复（2026-10-15）

网页输入已恢复。65.15秒持续检查254次，254次全部有效；数据年龄P95为0.329秒，最大0.355秒，没有新增UDP丢包。之后的真实浏览器检查显示“输入有效”，模型在线，推理和20步闭环按钮可用。修复过程没有启动模型推理或机械臂动作。

## 两个问题及证据

1. 相机进程与网页采集器的Fast DDS主机标识不一致，传输出现丢包。确认机器人Input=None、录制关闭后，通过现有Apex模块接口只重启相机，标识恢复一致，新增UDP丢包归零。
2. 仅修复通信后仍有延迟：60秒检查只有12/234次输入有效。独立订阅原始H.264话题，134个消息的源时间年龄中位数约0.573ms、最大2.944ms，证明上游发布已及时；网页采集器解码与RGB转换、缩放和JPEG处理共用接收回调，形成积压。由于状态按图像源时间匹配，滞后图像还会拖旧整组状态。

## 修改

`forcevla_web/collector.py` 将接收解码和图像加工分为两条线程：接收端处理每一个H.264压缩包，完成解码后放入容量为1的“最新帧”槽；另一线程只加工最新已解码帧。替换的是已经解码的图像，不丢弃尚需建立参考链的压缩P帧。

保留真实源时间和首次接收时间，未放宽0.75秒数据年龄与0.2秒偏差门槛。新增解码/加工耗时与已解码帧替换数诊断。四视角裁切、缩放、补边和JPEG训练对应流程不变。

6项采集器测试全部通过，包括H.264连续预测帧解码、加工延迟时只处理最新帧、时间戳保留、RGB/裁切/补边和输出节拍。代码检查通过。
