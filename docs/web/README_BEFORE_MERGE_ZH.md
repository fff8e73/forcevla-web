## 访问与使用

本机地址 `http://127.0.0.1:8096`；当前 Wi-Fi 地址 `http://172.30.1.208:8096`，Tailscale 地址 `http://100.64.0.106:8096`，也支持 `http://marvin-thor.local:8096`。有线地址6.6.8.100对应接口当前DOWN，不作为本次推荐访问入口。允许访问的主机名在 `config/local.json` 的 `allowed_hosts` 配置。

1. 等待模型在线、输入有效。默认任务文字来自现有验收样本，可以编辑。需要真机循环时点击“开始连续”；轮数、每轮步数和时长在“分段闭环”面板设置，点击“停止真机闭环”结束。
2. 点击“单次推理”，查看轨迹、夹爪范围、RPC耗时与观察至结果年龄。
3. 点击“本次快照”锁定该请求使用的四图；导出的NPZ保存实际送入模型的完整RGB数组与原始状态。
4. “开始连续”执行观察→推理→前K步真机动作→新观察的循环；“停止真机闭环”停止此循环。“停止推理”只结束仅推理会话，使在途结果失效，不代替真机停止按钮。
5. “刷新历史”选择以前的会话和预测，或导出ZIP。最新100个会话/每会话100条预测可在界面选择，ZIP包含所选会话的全部结果和事件。

同一浏览器的标签页共享会话身份；不同浏览器可查看，只有会话持有者能够停止会话。新页面由服务端发起心跳，浏览器收到后立即应答；影子推理超过10秒无有效心跳停止新调度，20步真机闭环的心跳超时为5秒。推理服务和采集本身不会因此关闭。服务重启将未完成会话标记为INTERRUPTED，不恢复执行。

## 当前图像接入的具体限制

2026-10-14 实测 `/quad_tile/compressed_undistorted` 是 H.264、1920×1488 的预览流。训练转换使用 `/recorder/quad_tile/compressed_undistorted` 的1920×1080录制流；本次没有启动录制或修改相机参数。

当前V1对预览流持续解码，按配置校验尺寸，将整幅图缩放至1920×1080，依次取左上/右上/左下/右下，再缩放至640×360、上下各补60行，执行与训练导出一致的JPEG95/4:4:4往返，生成640×480 RGB。模型服务负责后续224×224处理。H.264的所有P帧都会进入解码器，只有输出图像转换限流至约5Hz；帧时间来自解码帧对应的原消息时间，不能用转换完成时间刷新源年龄。

**5组近时间预览/录制帧的视野与颜色对照已通过；两条H.264编码并非逐像素相同，现场视角映射和曝光同步仍待验证。** 页面和每条预测元数据持续标注该限制；数值/时效有效仅表示可以开展影子诊断，不表示任务效果已验证。要完成原计划P2验收，还需对照训练录制链及离线同模型IK。拼图只有一个整体时间戳，不能据此声称四相机曝光同步。

2026-10-14 已定位并修复同机 DDS 网络上下文不一致导致的接收丢包：在录制关闭、机器人输入为空时，仅重启相机服务，恢复共享内存连接。没有调宽输入时效门槛，也没有修改系统网络缓冲。采集器现已记录连接诊断；发生类似网络变化时会提示，而不会自动重启相机。详见 [稳定性修复与验收](STABILITY_REPORT_ZH.md)。

视频和状态各使用独立ROS节点及执行器线程；TCP/力觉转换限流至50Hz，并使用每源最多100条历史反馈按图像源时间选择最近样本，保留所选样本原时间和夹爪反馈年龄，不刷新旧数据的时间戳。

## 安装与启动

要求系统已安装本机ROS2及OpenCV/NumPy/SciPy/Pillow，已有模型服务。Web虚拟环境与ROS虚拟环境分开；不安装Torch或重新加载模型权重。

```bash
cd /home/user/forcevla-web
bash scripts/install.sh
# 真实只读输入 + 已有模型服务
bash scripts/run.sh
# 独立模拟输入 + 模拟策略，绝不调用真实模型
bash scripts/run.sh --demo --port 8097
```

`scripts/run.sh` 与用户服务均启用经过验收的进程级内存分配设置，避免长时间处理大数组时积累过多保留空间。

`uv.lock` 锁定Web依赖；`requirements-collector.txt` 锁定PyAV。ROS虚拟环境保留系统包，避免替换ROS/OpenCV依赖的NumPy ABI。首次H.264订阅需要等待编码器关键帧；此时页面保持“等待输入”。

用户服务：

```bash
mkdir -p ~/.config/systemd/user
cp deploy/forcevla-web.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now forcevla-web.service
systemctl --user status forcevla-web.service
journalctl --user -u forcevla-web.service -n 80 --no-pager
```

停止网页使用 `systemctl --user stop forcevla-web.service`；它不停止原模型服务或机器人驱动。未启用user lingering的机器，需要用户systemd会话存在才运行用户服务。

默认服务只适用于可信局域网，使用会话Cookie、同源/Origin校验和CSRF令牌；没有多用户登录体系。新增访问域名需修改allowed_hosts并重启。不要启动多个Web worker；数据目录锁防止同目录重复启动，推理调度器只允许一个在途请求。

## 数据、时效与调度

`config/local.json` 配置模型地址、源尺寸、ROS域、IPC路径和保存位置。默认检查：接收年龄≤0.75s、源时间年龄≤1s、跨源接收/采样时间偏差≤0.20s；夹爪在消息接收年龄上叠加底层反馈年龄。时间戳必须是同一主机时间域对应的Unix时间，模拟时钟会被拒绝。这些是影子输入的初始诊断门槛，不是实机动作安全预算。

RPC超时15s，模型健康检查独立超时1s。不完整、非有限值、尺寸错误、坐标系错误、过期和不同步输入不提交。RPC失败退出当前会话并保留错误，不自动重试。观察持续独立采集；RPC不占用API事件循环；停止后的返回结果仍保存但标记discarded，不更新当前结果。

姿态沿用SciPy固定轴xyz外旋，位置m、姿态rad；原始力矩不旋转、不补偿，夹爪actual不再次归一化。模型输出是50×14绝对TCP/夹爪目标，不叠加实际位姿。

预览为约5Hz JPEG四图，未集成现有WebRTC播放器；这提供与当前模型输入布局一致的诊断画面。推理频率取决于服务耗时，不能与动作步长30Hz混为一谈。首次请求独立标记，P50/P95使用最多200个后续稳态样本。

`data/runs.sqlite3` 保存会话、事件、预测及压缩NPZ快照。每次请求记录任务、seed、配置版本、应用/RPC相同request_id、观察ID、源时间、动作和归一化动作、耗时、Web源码SHA256、现有部署清单与权重标识。源码和模型部署清单是取样时标识，不等于实时强制校验了模型启动参数。

默认4GiB日志配额，空间不足时停止新调度并报告错误。没有自动删除历史数据；归档整个数据目录后，在服务停止状态下移走数据库、WAL、SHM文件，重新启动。不要在服务运行中单独删除SQLite文件。浏览器慢连接不会创建无界事件队列；完整事件可通过REST按序号读取。

IPC采用 `/dev/shm/forcevla-web/observation.npz` 原子替换，读者获取完整副本。只有一个当前快照常驻；失去采集后保留数据显示为过期，不将旧帧伪装成新帧。
