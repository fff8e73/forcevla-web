# 夹爪无法“复位”的只读调查（2026-10-15）

本次订阅ROS反馈6秒、被动读取CAN帧2秒、查询参数，并查看当前四路画面。没有发布控制指令，没有改变目标、增益或标定，也没有执行开合实验。

## 已确认

1. `Restart Gripper` 不是回零动作。已安装 `DM_gripper.py` 的 `reset_motors_callback` 只失能两电机、等待0.1秒、再使能；没有重置 `q1/q2`，没有调用零位设定或重新标定。每个控制周期仍使用缓存目标发送MIT命令。
2. 运行参数两侧范围都是0～1.6rad，`auto_calibrate=false`。右爪归一化目标1.0对应1.6rad；不是1米、1毫米或关节角1rad。
3. 被动CAN采样直接确认，右电机ID=2收到的目标约1.599718rad，量化后的Kp约2.9304、Kd约0.11966。不是网页目标显示过期，也不是网页归一化换算错误。
4. 右电机反馈持续刷新：6秒收到1835份ROS样本，实际位置范围1.265927～1.267071rad，中位数1.266690rad；驱动力矩中位数约0.9695N·m。MOS及电机温度读数均39，状态码1代表已使能、无故障。反馈新鲜不等于目标到位。
5. 位置误差约0.333rad，结合总线上的MIT增益计算的力矩约0.974N·m，与反馈量级吻合：控制器仍在往旧目标施力，并未执行回零。
6. `/control/gripperValueL/R` 有VR/回放发布者注册，但6秒观察内没有收到新的目标消息。当前持续指令来自驱动缓存的旧目标，未发现其他控制器不断改写目标的证据。

## 对物理原因的判断

画面显示右夹爪接近闭合。实际位置几乎不变且有持续力矩，符合机械行程或接触限制的表现。结合固定配置上限1.6rad，可能是指爪已经到闭合端点、夹持物限制行程，或该配置上限超过当前实物的可达闭合位置。

这仍是根据只读数据的推断，不能据此唯一认定内部限位、外物阻挡或标定误差，也不能把1.267rad直接当成新的标定上限。没有通过本次检查证明电机损坏。

## 与接管失败的关系

右爪目标误差约0.333rad，超过驱动接管的0.05rad检查，因此重启后仍拒绝claim。删掉执行阶段的到位等待不能改变该接管结果；重复失能/使能也不改变缓存目标。

如果“复位”的预期是回到初始开口，需要明确的夹爪初始位置目标操作；当前按钮没有这一步。后续应在确认夹持状态后验证回到初始目标的响应，并核对实物可达行程，再决定接管目标/范围如何处理。本次未自动移动夹爪或放大力矩。
